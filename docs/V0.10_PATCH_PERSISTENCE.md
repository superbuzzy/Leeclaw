# LeeClaw v0.10 patch persistence contract

OpenClaw remains the only human identity and UI. Its trusted-proxy identity is converted by OpenClaw into a durable Profile; LeeClaw Workspace Core then maps that Profile to an OpenViking account and a server-held WeKnora tenant/knowledge-base scope. Browser requests never supply authoritative workspace, tenant, role, account, or credential values.

The OpenClaw Memory surface is backed only by `leeclaw-openviking`. The plugin owns `plugins.slots.memory`, so OpenClaw `memory-core` cannot automatically grow a second long-term store. `AGENTS.md`, `SOUL.md`, and `USER.md` remain bootstrap context. `MEMORY.md`, if present, is manual-only.

## Persistent

- `OPENCLAW_CONFIG_DIR` mounted at `/home/node/.openclaw`
- `OPENCLAW_WORKSPACE_DIR` and browser user data beneath that state volume
- Workspace registry and Workspace selection/session bindings
- OpenViking data, WeKnora data, and LeeClaw promotion/ontology volume
- `~/.openclaw/wk` only when the userland Chromium compatibility path is used

## Rebuildable

- Container writable layers, `/tmp`, caches, derived OpenClaw source, and build artifacts
- Chromium, its shared libraries, fontconfig, Noto CJK, and Noto Color Emoji are installed in the LeeClaw OpenClaw image

No persistent configuration may point to `/home/node/wk` or another container-writable resource. The default browser executable is `/usr/bin/chromium` in the image.

Run `cobra-knowledge/scripts/verify-v0.10.sh` for the unified acceptance check. Runtime checks activate automatically when `leeclaw-openclaw` is running, or explicitly with `LEECLAW_RUNTIME_VERIFY=1`. The destructive recreation test is deliberately guarded:

```bash
LEECLAW_DESTRUCTIVE_RECREATE=1 ./scripts/recreate-v0.10-test.sh
```

It removes only `leeclaw-openclaw` and `leeclaw-auth-gateway`, preserves mounted data, rebuilds them, and reruns the unified verifier without installing or repairing anything interactively.
